# 文本结构分析器

`scripts/analyze-references.mjs`

## 用途

对大量中文文本做**结构统计**，输出段落长度、句长配比、对话占比、感官词密度等指标。

设计场景：验证"提示词里写的写作规则"是否符合真实文本的分布。比如提示词要求
"每段 20–36 字"，这个区间是从哪来的？该工具用来给出实证依据。

**只统计，不采集内容。** 报告里不含任何原文片段。

## 用法

```bash
# 基础用法
node scripts/analyze-references.mjs --site bqg228 --pages 1 --limit 100

# 从 URL 列表读取（跳过列表页抓取）
node scripts/analyze-references.mjs --urls data/urls.txt --limit 100

# 输出到文件
node scripts/analyze-references.mjs --limit 100 --out report.md
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--site` | `xbiqugew` | 站点适配器（`bqg228` / `xbiqugew` / `alicesw`） |
| `--pages` | 3 | 抓取列表页数 |
| `--limit` | 40 | 最多分析多少条 |
| `--delay` | 350 | 请求间隔 ms |
| `--min-chars` | 800 | 低于此长度丢弃 |
| `--urls` | - | 从文件读 URL 列表 |
| `--out` | - | 输出文件 |

## 输出的指标

```
单章字数      均值 / 中位 / P10 / P90
段均字数      均值 / 中位
句均字数
短句占比      ≤10 字
长句占比      ≥30 字
对话段占比
开篇方式      对话 / 场景 / 其他
感官词密度    视觉 / 听觉 / 触觉 / 嗅觉 / 体感（每千字）
```

## 重要说明：这是风格分布，不是质量阈值

统计值描述的是"某一类文本**通常**长什么样"，不是"好文章应该是什么样"。

实测两个不同来源的样本：

| 指标 | 样本 A | 样本 B |
|---|---|---|
| 段均字数 | 34.5 | 27.9 |
| 对话段占比 | 4.8% | 27.6% |
| 触觉密度 | 10.5 | 4.2 |

对话占比差近 6 倍。两者都是正常写作，差异来自题材与风格选择。

**正确用法**：知道主流分布在哪，然后有意识地决定跟随还是偏离。
如果你要写对话驱动型文本，就不该照抄 4.8% 这个值。

## 站点适配器

不同站点结构不同。适配器抽象四件事：

```js
{
  listUrl(page)   // 列表页 URL
  bookHrefs(html) // 从列表页提取条目
  chapters(html)  // 从目录页提取章节 URL
  body(html)      // 提取正文（处理各站的反爬）
  paginate(url)   // 正文分页后缀
  blocked(html)   // 拦截页识别
}
```

### 已知的反爬形态

| 形态 | 说明 | 处理 |
|---|---|---|
| **Base64 正文** | 正文藏在 `qsbs.bb('...')` 调用里 | 提取并解码 |
| **正文分页** | 单页仅 500–1000 字，章被拆到 `_1` `_2` | 合并分页 |
| **壳页** | 部分章节返回占位页（正文仅 200 余字） | 识别并丢弃 |
| **限流** | HTTP 200 + 极短拦截页 | 识别并中止，不静默计入失败 |

**壳页是隐蔽的陷阱**：如果不过滤，占位内容会混入统计，导致指标失真。
（实测未过滤时对话占比被算成 0.0%。）

## 采集边界

| 项 | 做法 |
|---|---|
| 抓取范围 | 仅正文容器，不含导航/评论/推荐 |
| 落盘内容 | **不落盘任何原文**，分析完即丢弃 |
| 报告内容 | 只有统计量 |
| 请求频率 | 默认 350ms 间隔，可调 |

参考站点的作品版权归原权利人所有。本工具用途是提炼写作方法论，
不是内容再分发。

## 添加新站点

在 `ADAPTERS` 对象里增加一项即可：

```js
mysite: {
  label: "站点名",
  base: "https://example.com",
  listUrl: (p) => (p === 1 ? "/" : `/list/${p}.html`),
  bookHrefs: (h) => [...new Set([...h.matchAll(/href="(\/book\/\d+\/?)"/g)].map(m => m[1]))],
  chapters: (h) => [...new Set([...h.matchAll(/href="(\/book\/\d+\/\d+\.html)"/g)].map(m => m[1]))],
  paginate: () => [],
  body: (h) => {
    const m = h.match(/<div[^>]*id="content"[^>]*>([\s\S]*?)<\/div>/i);
    return m ? m[1] : null;
  },
  blocked: (h) => (h.length < 500 ? "空页" : null),
}
```

调试建议：先用浏览器打开一章节页，查看正文容器的 `id`/`class`，
再确认是否需要处理 Base64 或分页。
